# JPA / Hibernate

## Description

This module demonstrates a basic persistence layer implemented with JPA annotations and Hibernate.

The project contains a simple domain model, a generic controller interface, an abstract Hibernate-based controller, and a concrete controller for the `Country` entity. The goal of this challenge is to show how CRUD-style database operations can be organized around entities, controllers, Hibernate sessions, and transactions.

## Main concepts

The module demonstrates the following concepts:

* mapping Java classes to database tables with JPA annotations;
* using Hibernate `SessionFactory` and `Session`;
* implementing basic CRUD operations;
* organizing persistence logic through a generic controller interface;
* using an abstract base controller to share common database operations;
* creating a concrete controller for a specific entity type.

## Domain model

The central entity in this module is `Country`.

It is mapped to the `country` table:

```java id="heq6ny"
@javax.persistence.Entity
@Table(name = "country")
public final class Country implements Serializable, Entity {
    @Id
    @GeneratedValue(strategy = GenerationType.AUTO)
    private int id;

    @Column(name = "name", nullable = false)
    private String name;
}
```

The `Country` entity contains:

* `id` — primary key generated by Hibernate;
* `name` — required country name.

## Controller layer

The `Controller` interface defines common operations for persistent entities:

```java id="sk6klq"
List<E> getAll();
boolean insert(E entity);
boolean update(E entity);
boolean delete(K id);
E getEntityById(K id);
K getIdByEntity(E entity);
```

This interface makes the persistence API consistent across different entity types.

## Abstract controller

`AbstractController` provides shared Hibernate-based implementations for common operations:

* `insert(E entity)`;
* `update(E entity)`;
* `delete(K id)`;
* `getIdByEntity(E entity)`.

Each operation uses a Hibernate `Session` and transaction management:

```java id="7xpn8t"
session.beginTransaction();
session.save(entity);
session.getTransaction().commit();
```

If an insert operation fails, the transaction is rolled back.

## Country controller

`CountryController` is a concrete controller for the `Country` entity.

It extends the abstract base controller:

```java id="tq3my2"
public class CountryController extends AbstractController<Country, Integer>
```

It implements entity-specific read operations:

```java id="k7l2iq"
public List<Country> getAll()
public Country getEntityById(Integer id)
```

The controller is implemented as a singleton:

```java id="gwbkk6"
private static final CountryController COUNTRY_CONTROLLER = new CountryController();
public static CountryController getCountryController() {
    return COUNTRY_CONTROLLER;
}
```

## Hibernate configuration

Hibernate initialization is centralized in `HibernateUntil`.

The class builds a single `SessionFactory` from the Hibernate configuration file:

```java id="o7g86p"
private static final SessionFactory sessionFactory =
    new Configuration().configure().buildSessionFactory();
```

The `SessionFactory` is then reused by controllers to open Hibernate sessions.

## Persistence flow

A typical insert operation follows this flow:

```text id="wjzu7f"
Country entity
    ↓
CountryController
    ↓
AbstractController.insert(...)
    ↓
Hibernate Session
    ↓
Transaction
    ↓
Database
```

A typical read operation follows this flow:

```text id="d3siua"
CountryController.getEntityById(id)
    ↓
Hibernate Session
    ↓
session.get(Country.class, id)
    ↓
Country entity
```

This module demonstrates practical knowledge of:

* JPA entity mapping;
* Hibernate session usage;
* transaction boundaries;
* generic interfaces and abstract classes;
* reusable CRUD controller design;
* separation between model, controller, and utility layers;
* basic persistence-layer architecture in Java.

## Notes

This is an educational module focused on the structure of a Hibernate persistence layer. It is intentionally small and centered around a simple `Country` entity, while the controller architecture is generic enough to be extended to other entities.
